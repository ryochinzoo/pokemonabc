# Submission Checklist

Kaggle提出前に確認すること。目的は、ロジック改善後の実行時エラー再発を防ぐこと。

## 必須チェック

- `DEBUG_SELECTION = False` になっていること。
- `DECK` が60枚であること。
- ACE SPECが2枚以上入っていないこと。
- `python -m py_compile src/input/datasets/decks/mega-starmie-ex-deck/main.py` が通ること。
- 初期観測で `agent()` がデッキを返すこと。
- 直近のエラーリプレイの全 `observation` を `agent()` に食わせて落ちないこと。
- 新規参照したAPIフィールドが、全ログで必ず存在する前提になっていないこと。
- `getattr()` / `hasattr()` / `TODO` が提出用 `main.py` に残っていないこと。
- `cg` ディレクトリは参照のみ。提出コード修正では触らないこと。

## 再発防止チェック

- `__file__` を直接使わない。Kaggle raw Python実行では未定義になることがある。
- `Option.cardId` が無い/Noneの選択肢でも、手札・山札・トラッシュからカードIDを解決できること。
- `Pokemon.playerIndex` など、ログによって存在しない可能性があるフィールドを直接読まないこと。
- `Attack.damage == 0` の技を、0ダメージ技と決めつけないこと。
- 可変打点は手札枚数やテキストに応じた実効ダメージで評価すること。
- 相手デッキの基本エネルギーIDもタイプ変換できること。水/悪だけに限定しない。
- エネトラッシュ枚数やコイントスなど、相手の可変技も0ダメージ/固定ダメージ扱いしないこと。
- ワザ2用の2枚目・3枚目エネを、即時打点が増えないという理由で低評価にしないこと。
- 複数選択、SKILL_ORDER、DRAW_COUNTなどで空配列や不正個数を返さないこと。
- RETREAT選択肢にベンチ対象が直接入っていない場合も、内部で退却先を選べること。
- 相手スタジアムが場にある時、こちらのスタジアムを貼る価値と捨てない価値を両方見ること。
- 重要カードをハイボ等のコストで雑に捨てないこと。
- レガシーエネルギー採用中は、ヒーローマントなど他のACE SPECを同時採用しないこと。
- `effect` / `contextCard` のカードIDは `id` と `cardId` の差で判定漏れしないこと。

## これまでの提出エラー

### `__file__` 未定義

症状:

```text
NameError: name '__file__' is not defined
```

原因:

Kaggleのraw Python実行環境で `__file__` が定義されない場合がある。

再発防止:

ファイルパス初期化は `__file__` 依存だけにしない。

### `Option.cardId` 依存

症状:

カード選択や進化・エネ貼りで不正選択、または選択不能。

原因:

`Option.cardId` が常に入る前提で、`area/index/inPlayArea/inPlayIndex` を十分に解決していなかった。

再発防止:

`board.option_card_id(option)` を通して解決する。

### SKILL_ORDERで空行動

症状:

特性順選択で `[]` や `None` を返してエラー。

原因:

`minCount/maxCount` がある選択で、必要数を満たさない行動を返していた。

再発防止:

全選択で `minCount <= len(action) <= maxCount` を守る。

### 可変打点が0扱い

症状:

メガユキメノコが相手手札6枚でも攻撃価値を認識しない。

原因:

`Attack.damage == 0` の `Resentful Refrain` を0ダメージ扱いしていた。

再発防止:

`effective_attack_damage()` で実効ダメージを評価する。

### `Pokemon.playerIndex` 非存在

症状:

```text
AttributeError: 'Pokemon' object has no attribute 'playerIndex'
```

原因:

リプレイ/提出環境の `Pokemon` に `playerIndex` が無い個体があり、可変打点計算で直接読んでいた。

再発防止:

自分のポケモンかどうかは `BoardState` 内の自分側リストとの同一性で判定する。

### ACE SPEC二重投入によるデッキエラー

症状:

```text
Player 1's deck error.
status: INVALID
```

原因:

レガシーエネルギーとヒーローマントを同時採用した。どちらもACE SPECで、デッキにはACE SPECを1枚しか入れられない。

再発防止:

構築変更後にカード表の `aceSpec` を集計し、ACE SPECが1枚以下であることを確認する。

### ヒーローマント誤装着

症状:

```text
Snorunt hp170/170
```

原因:

ヒーローマントの対象選択で `effect/contextCard` のカードID判定が抜け、汎用味方ターゲット評価に落ちていた。

再発防止:

ヒーローマント選択時は `HeroCapeStrategy.evaluate_attach()` を通し、対象をメガスターミー/メガユキメノコに限定する。地下闘技場ログで `Snorunt hp170` や通常ユキメノコ等の不自然なHP上昇がないことを確認する。

## ロジック劣化チェック

- 通常ユキメノコがメインアタッカー化していないこと。
- マシマシラがバトル場に居座っていないこと。
- ヒトデマン/メガスターミーより通常ユキメノコへ水エネを優先していないこと。
- フーディンライン相手ではメガユキメノコ軸に寄ること。
- フーディンライン相手では、ユキワラシを手札から出す/山札から取る評価がヒトデマン軸に負けすぎないこと。
- Hand Trimmerは相手手札6枚以上、特にフーディン系や完成主力が見えている時に妨害札として評価すること。
- Hand Trimmerはメガユキメノコの `Resentful Refrain` 打点を下げるため、今倒せる/高打点が出る時は使わず攻撃を優先すること。
- Hand Trimmerを外している構築では、メガシグナルで自分の主力完成を優先すること。
- ハイパーボール等のトラッシュコストで、Hand Trimmer/ヒーローマント/メガ進化札の保護スコアが打ち消されず、Crispinや余剰ポケパッドなどから捨てること。
- イワパレス相手では、EX/メガEXの攻撃を本体に通る前提で評価しないこと。通常ユキメノコ等の非EX軸へ寄せること。
- イワパレスがアクティブで、こちらが攻撃可能かつベンチを倒せる時は、ボスの司令で壁をどかす選択を見ること。
- メガルカリオexが完成して居座り、こちらの準備が遅れている時は、ボスの司令で低火力/逃げづらいベンチを呼んで1ターン稼ぐこと。
- ボスの司令は、ドラメシヤ/ドロンチ、リオル、ケーシィ/ユンゲラー、ジュラルドン系などの進化前を呼んで相手の勝ち筋を崩す用途でも評価すること。
- イワパレスが見えている時は、非EXたねを安易にメガEXへ進化して攻撃不能にしないこと。
- イシズマイ段階では、イワパレスになる前に優先して倒す/ボスで呼ぶこと。
- ドラパルト系は、ドラメシヤ/ドロンチ段階で優先して倒し、ドラパルトexが立ったらボスで呼んで処理すること。
- シェイミがいる時は、ベンチ非ルール持ちへの攻撃ダメージを通る前提で評価しないこと。
- メガスターミー/メガユキメノコのワザ2完成に向けてエネを集めること。
- 危ない廃墟を、相手スタジアムがある時に貼り返せること。
- マシマシラ＋悪エネの見込みがない時は、危ない廃墟を序盤の置き得として貼らないこと。
- ベンチ0の単騎盤面で、進化札やスタジアムより先にバックアップ用たねを探しに行くこと。
- ベンチ0の単騎盤面で、進化札を取るなら通常進化ではなくメガ進化を優先すること。
- ユキワラシなど準備役の低打点攻撃は、倒せないならリーリエ・ゼイユ・ボール系などの展開札より優先しないこと。
- イベルタルは壁役として扱い、倒せない攻撃や無意味な火力上昇のために退却・エネ貼りしないこと。
- マシマシラは初手バトル場候補として高評価にしないこと。
- メガシグナル/ハイパーボールでメガスターミーへ触れる時は、ポケパッドでヒトデマンを優先して取ること。
- ヒトデマン/メガスターミーはデフォルト評価ではなく専用Strategyで評価すること。
- 安全なメガユキメノコが既にいる時は、2体目メガユキメノコよりヒトデマン/メガスターミー線を優先すること。
- メガスターミーが手札にある時はヒトデマン、ヒトデマンが場にいる時はメガスターミーを探索候補として明示的に上げること。
- 倒せない攻撃の前に、スタジアム・リーリエ・ゼイユ・ボール系・タンカ等の展開札を確認すること。
- メガスターミー軸では、倒せない攻撃の前に使える展開札を使うこと。手札を溜めるフーディン的な動きに寄せないこと。
- `END` は、同じ選択画面に合法な展開札/進化/エネ貼り/特性がある時に選ばないこと。
- カードIDが取れない `PLAY` 選択肢も、攻撃/終了前の有効行動として評価すること。
- 相手を倒せる攻撃がある時は、ポケギア/ボール/退却/ENDより攻撃を優先すること。
- 主力メガが次ターンに倒される時は、未来育成より今できる攻撃を優先すること。
- メガスターミー同士・メガユキメノコ同士の退却は、明確な耐久理由なしに選ばないこと。
- メガスターミー/メガユキメノコ間の退却は、火力・KO・耐久退避の明確な理由がある時だけ選ぶこと。
- 攻撃できる/倒せる/瀕死回避になるメガ交代は、過剰に抑制しないこと。
- ゼイユを複数枚抱えて盤面が細い時は、重要札警戒だけで抱え続けず、1枚目を展開札として使うこと。
- バトル場とベンチに同じヒトデマン/ユキワラシがいる時、バトル場側は囮として扱い、エネはベンチ側を優先すること。
- ヒーローマントをユキワラシ、通常ユキメノコ、マシマシラ、イベルタルへ付けないこと。
- ミツルの思いやりは20〜40程度の軽傷で使わず、メガEXが大きく削られた時か倒される危険がある時だけ使うこと。
- 水エネは主力ラインを優先し、イワパレス対面の通常ユキメノコ以外の非主力・壁役へ雑に貼らないこと。
- メガスターミー/ヒトデマンが見えている時は、通常ユキメノコやユキワラシへ水エネを逃がさないこと。
- 水エネが少ない時は、メガスターミー軸かメガユキメノコ軸の片方にサーチ/進化/水貼りを寄せ、二方面育成で両方止まらないこと。
- 水エネ不足時は、水エネを退却コストで捨てて殴れないメガを前に出さないこと。
- メガユキメノコに進化できる時は、ユキワラシへの水貼りより進化を先に見ること。
- アクティブのユキワラシが倒される危険があり、ベンチにもユキワラシがいる時は、ベンチ側をメガユキメノコへ進化させること。
- エネ貼り前に、アイテム/ポケモン展開/手札の進化先を先に確認すること。攻撃可能性の評価はその後に行うこと。
- マシマシラに悪エネがあり、自分の場にダメカンがある時は、攻撃や終了前にアドレナブレインの特性ボタンを押すこと。
- マシマシラ未展開で自分の場にダメカンがある/悪エネがある時は、ベンチに出す選択を攻撃やENDより優先して見ること。
- マシマシラのダメカン移動は、同じ自分ポケモンから取り、同じ相手ポケモンへまとめて載せること。
- メガスターミーのベンチ50、危ない廃墟、ユキメノコ、マシマシラのダメカンは、相手の進化前ラインを優先して見ること。
- イベルタルは壁だけでなく、`Clutch` による逃げ封じで相手主力/進化前/イワパレスを拘束する用途を評価すること。
- ポケギア3.0の候補は `AreaType.LOOKING` からカードIDを解決し、空選択を返さずサポートを選ぶこと。
- 通常ユキメノコの `いてつくとばり` は手動で押す特性ではなく自動特性。相手の特性持ちが多い時は、進化/維持する価値を評価に反映すること。
- リーリエのピッピexの `Full Moon Rondo` はベンチ数で160点以上になり得るため、相手火力予測で20点固定にしないこと。
- イワパレスをボスでどかす時は、倒せるベンチ/低HP/逃げづらい相手を優先して呼ぶこと。
