# council — 4専門家評議会

2026-07-20の実例: v3棄却後にこの型で回し、「提出版のセグフォ穴」「測定近親交配」
「汎用MCTSの機構的故障」「壁裁定」を一晩で摘出した(D19, plan-2026-07-20-council.md)。

## 手順

1. **Agentツールで4体を並列起動**(general-purpose、background、**`model: "fable"` を明示指定**)。
   モデル指定を省くと4役が親セッションのモデルを継承する。評議会はこのプロジェクト唯一の
   「組織的にバイアスを外す装置」であり、設計欠陥の摘出(D36: ccのBoss'sプローブの交絡)は
   素の推論力がそのまま出力品質になるため、**親が何であれ最高知能を明示的に割り当てる**。
   共通ルールを全員に:
   - **一次資料を自分で読む**(要約を渡さない): docs/memo/decisions.md、data.md、
     CLAUDE.md、関連コード。足りなければ自分で探す。
   - **既存決定への遠慮を明示的に禁止**(「D17に反してよい」等と書く)
   - **bench.py/selfplayの実行禁止**(CPUは測定用に予約。静的分析のみ)
   - 出力は日本語・800語以内・ランク付き・decision-ready
2. 4役のプロンプト骨子:
   - **戦略**: 審査配点から逆算した資源配分。各基準の最高レバレッジ成果物とコスト。
     kill基準とタイムボックス。「既存計画と変えることを1段落で」を必須要求。
   - **赤チーム批判者**: 前提・盲点・自己欺瞞をTOP5で。各項目に「挑戦する前提/
     なぜ間違いうるか/重大度/それを確認または殺す安価なテスト」。最後に
     「最初に着手すべき1つ」。攻撃面の例示(測定の近親交配・メタ鮮度・統計検出力・
     アーキテクチャの天井・プロセスリスク)は与えるが「自分で見つけよ」と書く。
   - **ドメイン専門家**(ポケモンTCG): カードDB(verification/data/)とデッキリストを
     ID解決して読み、カード名を引用した具体診断。介入策を期待効果/難度/測定法付きで。
   - **実装の達人**: 対象コードを読み、故障の機構的説明→最小差分の設計→
     工数見積り→段階測定プロトコル(合格閾値付き)。
3. **並行して、誰の結論でも必要になる実測(プローブ等)を1本仕込む**。
4. 全報告到着後: 一致点(=バイアスの少ない結論)と相違点を分け、相違は裁定して
   理由を書く。統合計画をdocs/memo/plan-<date>-council.mdに保存、decisions.mdにDn。
5. ユーザー判断が必要な項目(提出・デッキ転換・チーム合意)を明確にリスト化。

## 教訓

- 専門家の予想も外れる(ドスクライン実験: 予想-5〜-10ptが実測+14.7pt)。
  **評議会の提案も必ず実測で検証**。評議会は仮説生成器であって裁定者ではない。
- 4体の合意点は強い。1体だけの主張は「安価なテスト」を先に。
