## 背景(責めない事実確認)

- 最終順位は**直近2提出のみ**で決まる(Kaggle仕様)。
- これまでに、ゲート未通過の提出が直近2枠からチーム歴代ベスト版を押し出す事象が2回発生
  (例: 643.8達成中のv2.1×Kangaが未検証版に置換)。個人の落ち度ではなく**仕組みの不在**が原因。
- 賞金の主戦場はStrategy部門(Model70%のうちSim成績は1項目≈14%)。順位の瞬間風速より
  「ベスト2本が常に最終枠にある」状態の維持が全員の利益。

## ルール案(5条)

1. **ゲートPASS必須**: 提出前に verification/README.md のフルゲート
   (vs random ≥96% / 3ゲージ / donk非悪化 / steel族外非退行 / CRASH=0)を通し、
   数値をチームチャットに貼ってから提出する。
2. **事前宣言**: 提出の30分前までに「何を・なぜ・どの枠を消費するか」を宣言し、
   直近2枠のどちらが押し出されるかを明示する。
3. **枠予算**: 較正・実験目的の提出は「後でベスト2本を出し直す」までがセット
   (押し出したまま放置しない)。1日5枠のうち2枠は常にベスト再提出用に温存。
4. **凍結日**: **8/13以降は新規変更の提出禁止**。8/13-16は「実証済みベスト×2の
   同一提出」のみ(Scoring分散対策、D11-4)。
5. **記録**: 提出は docs/memo/decisions.md にDn形式で記録(ref番号・ゲート数値・意図)。

## 運用メモ

- ゲートは `cd <デッキdir> && python3 ../../../../../verification/bench.py 300` 系で
  ~30分。手順は verification/README.md 参照。回し方が不明ならゆうじ/ccに依頼でOK。
- このルールは**お互いの実験を止めるためではなく**、実験を安心して打てるようにするための
  もの(較正提出も宣言+復旧セットなら歓迎)。
