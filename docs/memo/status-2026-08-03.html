01何を変えたか — 記事を凍結して、デッキ軸へ

ゆうじの承認で2つ決めた。①Strategy記事は8/16まで凍結(手を触れない) ②デッキ転換を検討対象に入れる。

凍結の根拠 — 時間が非対称だった

Sim(オンライン)は残り14日。Strategy記事は残り42日で、 うち29日は提出が終わった後。しかも運営は「締切後およそ2週間、 凍結したエージェント同士の対戦が続く」「締切後はエピソード配信頻度を上げる」と明言している。 記事は後で書ける。オンラインだけが戻らない。

そもそも我々の運用規範(playbook §7)は「8/17以降=執筆」と決めてあった。 記事から逆算していたのは自分たちの規定を先食いしていた状態で、 凍結は規定に戻すだけだった。

そして「記事から逆算する作戦が邪魔をしている」というゆうじの指摘は、仮説ではなく再発だった。 D62の本文に「この懸念は当たっていた」と既に書いてある。そして私は今日それを再現した — 地図が変わった直後に、決まっている実行列の項目に直行した。2例目。

hyper-optimized simulation agent is interesting, it doesn't tell the whole story behind the Pokémon TCG, gameplay, deckcrafting, and underlying strategic decisions that go into playing a top tier deck. Kaggle運営スタッフ / Strategy部門の固定スレッド(我々は未読だった)

運営自身が「deckcrafting」を名指しで評価軸に挙げていた。 ゆうじの「記事が面白くない」という直感は、運営の評価軸と一致していた。

02最大の実測 — デッキだけで60pt動いた

main.py(操縦者)を1バイトも変えず、deck.csv だけを 実ラダーから抽出した本物のデッキに差し替えて、同じ相手(Alakazamゲージ)と200戦ずつ戦わせた。

我々の操縦者 × このデッキ事前予測実測差
tarountula84.8%94.5%+9.7
crustle55.0%85.0%+30.0
starmie(現行=対照)44.7%57.0%+12.3
garchomp39.4%51.5%+12.1
grimmsnarl58.1%35.0%−23.1
桁が違う

同じ操縦者・同じ相手で、35.0% 〜 94.5% = 60pt。 対照(現行デッキ)の57.0%は、前回D61で測った57.3%をほぼ完全に再現したので、 測定環境そのものは健全だと確認できている。

比較のために書くと、我々が7ヶ月かけて測った操縦者側の最大の介入 (探索・上書き層をまるごとON/OFFした対照実験)は +13.62pt だった。 デッキ軸はその4倍以上の幅を持っている。

測定前に予測を封じてから測った。予測は実ラダーの対面勝率をそのまま使った。 結果、予測した順序は壊れた — grimmsnarl は予測2位から実測5位へ、23pt落ちた。 これは「デッキの強さはそのまま我々に移らない」ことの直接の証拠になる。

03なぜそうなるのか — 機構が特定できた

我々の操縦者が特性(ポケモンの能力)を扱うコードは、これだけである。

main.py:335 — 全部で3行

idx = first(lambda o: o.type == OptionType.ABILITY)

if idx is not None: return [idx]

提示された最初の特性を、中身を見ずに押しているだけ。 どの特性か、何を対象にするか、使うべきかは一切判断していない。

そしてホスト(運営)の裁定では、特性には2種類ある — ABILITY = 明示的に選ぶ行動 と SKILL = 受動・常在で自動適用。 ここで綺麗に割れた。

デッキ強さの動力源選択の要否我々の実測
tarountula Articuno「Repelling Veil」= 相手の攻撃の効果を無効化(常在) 不要 94.5%
crustle Crustle の壁(常在)+ 高耐久 運用が要る 85.0%
grimmsnarl Munkidori = ダメカンを最大3個「どこからどこへ」移す / Punk Up = 悪エネ5枚を「好きなように」配分 選択が必須 35.0%
得られた原理(機構つきの仮説)

我々の操縦者が引き出せるデッキ性能は、そのデッキの動力源が 「常在効果」か「能動的な対象選択」かで決まる。 前者は操縦不要で満額出る。後者は先頭選択の盲打ちになり、実ラダーより20pt級で劣化する。

tarountula が Alakazam を狩る理由も機構で説明できた。 Alakazam の攻撃「Strange Hacking」はダメージが n/a — こんらん付与とダメカン移動という純粋な"効果"しか持たない。 Articuno の Repelling Veil は、その効果を丸ごと無効化する。 外部の3つの独立した観測(公開分析72% / 実ラダー84.8% / 我々の測定94.5%)が 同じ向きで、機構つきで一致した。

この実験は「前例のない向き」だった

公開されている最大の先行研究(citerne)はデッキを固定して操縦者を入れ替える実験をした。 我々が今日やったのは操縦者を固定してデッキを入れ替える — その直交補で、291件の公開ノートブック監査でも前例がなかった。

これは深夜の超会議で出た未解決の問い 「我々の計器は全部デッキ固定・操縦者可変の設計。逆を一度もやっていない。道具の向きが逆では」 への回答でもある。

04デッキの成績表 — 3つのゲージで掃引した

1つの相手だけで判断すると誤る。較正済みのゲージ3体(Alakazam / Lucario / Archaludon)に 全デッキをぶつけた。合計1,600戦、全セル CRASH=0。

デッキAlakazamLucarioArchaludon フィールド加重vs random(安全)
crustle85.0%39.0% 75.0%71.5% 78.3% 失格
tarountula94.5%60.5% 9.0%68.8% 98.3% 通過
starmie(現行)57.0%48.0% 27.0%48.7%—(王者)
grimmsnarl35.0%31.5% 18.5%30.8%95.8%

現行比: crustle +22.8pt / tarountula +20.1pt / grimmsnarl −17.9pt。

読み取れる形

  • tarountula は「専門家」だった。事前の実ラダー予測どおり — Alakazam に94.5%、しかし Archaludon に9.0%。 1つのゲージだけで判断していたら完全に誤っていた。
  • crustle は逆の形。我々の最悪対面である Archaludon を 27.0% → 75.0%(+48pt)に改善するが、Lucario で39.0%に沈む。 そして安全フロア(vs random ≥96%)を割るので、このままでは提出できない。

05分かっていないこと — ここを隠さない

覆域は53.1%しかない

較正ゲージがあるのは Alakazam(29.2%)・Lucario(13.2%)・Archaludon(10.7%)の3つだけ。 grimmsnarl(19.3%)と crustle(13.5%)= フィールドの32.8%は測れていない。

しかも tarountula は実ラダーで grimmsnarl に35.7%で負けるので、 真のフィールド加重は上の表より低い。

穴を実ラダーの数字で埋めることは禁止にした。 実ラダーの値は「そのデッキをその持ち主が操縦した」数字であり、 grimmsnarl では我々の操縦者が 58.1% → 35.0% と23pt落としている。 混ぜれば、今日4回踏んだのと同じ「単位の取り違え」になる。

Grimmsnarl のゲージが作れない

埋めるべき穴は Grimmsnarl だと分かっている。デッキは既に手元にある (実ラダーの723体中505体が完全一致する標準形を抽出済み)。足りないのは操縦者だけ。

そこで公開ノートブック291件を検索したが、Grimmsnarl を自分のデッキとして使っている エージェントは0件だった。

Marnie's エージェントを競争力のある水準で作るのが一番簡単。単にデータが大量にあるから。 それがさらに Marnie's を増やすサイクルを生む。集中しすぎて負債になるまで。 Jake(Sim部門 8位)/ 公開掲示板

Grimmsnarl は 1000-1099帯で 33.5% = 最大勢力なのに、誰も公開していない。 皆リプレイから模倣学習していて、公開スケルトンから作っていないから。 この事実自体が、レポートに書ける観測になる。

他にも留保がある — 各ゲージは操縦者1体なので絶対値は楽観側に出る。 ミラー戦は未測定。そしてこれは層S(スクリーニング)であって、採否判断には使えない (採用には Neyman N=3,200 の本測定と安全ゲート一式が要る)。

06今日4回踏んだ罠 — これ自体が記事の材料になる

今日は同じ型の測定ミスを4回踏んだ。全部「統計的に有意かどうか」ではなく、 「何を1と数えるか」と「何を黙って捨てたか」だった。

#誤り実体
1外部データがチーム単位、我々の計器は遭遇単位 前日の決定(D62)の統計的根拠が成立しなくなった
2「上位帯は crustle が60.8%」 distinct なチーム数では crustle 4体 vs grimmsnarl 67体。 少数のエージェントが大量に試合していただけ
3「800帯は lucario が30.8%」 1体(725戦)の寄与。斥候を広げたら 18.4% に落ちた
4自作の計算器が標本の少ないセルを黙って除外 たまたま負け対面2つだけが落ち、あるデッキの評価が +8.1pt 水増しされた
4件に共通すること

計器はどの場合も、堂々と信頼区間つきの数字を出していた。 間違っていることを教えてくれる仕組みは、どこにも無かった。 これは我々が以前から書いている「実験設計には計器が無い」という主張の、 同じ日に4例の実証になった。

対策として、計器そのものに「distinct な提出数を必ず併記する」 「落としたセルを必ず開示する」を組み込んだ。次から自動で見える。

07次の一手

私が進めること(承認不要)

  • crustle が安全フロアを割る機構の特定。 仮説は立っている — この構成は Mega Kangaskhan ex(倒されるとサイド3枚)を抱えていて、 我々の操縦者はバトル場に出す個体を「エネ枚数→打点→HP」で選び、 サイド負債を一切見ていない。HP300の負債を前に出して献上している疑い。 同じ欠陥は現行デッキにもある(Mega Starmie ex も3枚、それを4枚積んでいる)。
  • これは機構が特定済みの操縦者修理なので、我々の規範では最優先の標的になる。 直せば現行デッキも crustle も同時に良くなる可能性がある。
  • Grimmsnarl の穴は「埋められない」ことを限界として明記したうえで進める。

ゆうじの判断が要ること

  • 提出。tarountula は安全ゲートを通り、フィールド加重で現行比 +20.1pt。 ただし層Sの数字なので、このまま出すのは我々の規範違反。 本測定(層B)を通すか、それとも「本番を計器として使う」プローブとして出すかは、 枠の使い方の判断になる。数字を揃えてから改めて持っていく。
  • デッキ転換そのものは既に「検討対象に入れる」承認をもらっているが、 実際に王者を差し替えるのは別の決定。
率直な現状評価

ゆうじの読みは当たっていた。デッキ軸には、操縦者軸の4倍以上の余地があった。 ただし「上位デッキに乗り換える」だけは外部データが正面から否定している (公開された74,634試合の分析: LBで支配的に見えた時点で、そのデッキの優位は既に消えている)。 だから基準は「上位が使っているか」ではなく 「フィールドに対するEV × シェアの低さ」に置いた。 tarountula(シェア3.2%)がその基準で最初に上がってきた候補になる。
