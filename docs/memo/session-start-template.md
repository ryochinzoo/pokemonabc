# セッション開始テンプレ（ゆうじ → Claude）

セッションの最初にこれを貼る。**5行で足りる。** 目的は「Claudeが古い前提で走り出すのを防ぐ」こと。

2026-08-11 に実例が出た: Claude は「我々は678.7点」という前提で1時間以上作業したが、
実際には前日に **821.9点の提出**が入っていた。**比較対象のデッキごと間違えていた。**
Claude は自分から提出一覧を見に行かない限り気づけない。

---

## 貼る内容

```
【今日決めたいこと】 ＜1行。「調べて」ではなく「何を決めるか」＞
【前回から変わったこと】 ＜提出した / チームメイトが動いた / レートが動いた＞
【私の見立て】 ＜今こう考えている、という一言。外れていてよい＞
【触ってほしくないもの】 ＜あれば＞
【今日の持ち時間】 ＜何時間見れるか＞
```

### 記入例

```
【今日決めたいこと】 8/13凍結の最終2枠をこのままにするか、差し替えるか
【前回から変わったこと】 昨日15:48に starmie-mastercontrol(821.9)と starmie-aggro(674.0)を提出
【私の見立て】 821.9が今のベスト。触らないほうがいい気がしている
【触ってほしくないもの】 最終2枠。提出は私の承認なしに絶対しない
【今日の持ち時間】 2時間
```

---

## なぜこれが効くのか

- **「決めたいこと」があると、Claudeは調査を打ち切る判断ができる。** 無いと、面白い枝を
  延々と掘る（2026-08-10 のプレイングミス調査は、結局ゼロ件で終わった。
  「デッキを替えるか決めたい」が先にあれば、もっと早く切り上げていた）
- **「私の見立て」は当たっている必要がない。** 外れていればClaudeがそう言う。
  見立てが無いと、Claudeは何を否定すればいいか分からず、無難な報告に寄る
- **「変わったこと」が最重要。** Claudeはリポジトリを読めるが、
  **Kaggleの最新状態と、ゆうじの頭の中は読めない**

## Claude 側の義務（テンプレが無いときも）

1. セッション開始時に `kaggle_cli.our_submissions()` を1回叩いて**現在の提出状況を確認する**。
   古い前提で走らないための最小コスト（1リクエスト）。
2. 「今のチャンピオンはどれか」を確定してから、デッキ比較の類を始める。
3. 提出・デッキ転換・判定規則の変更・チーム合意は**必ず承認を取る**（playbook §7.5）。

## 提出したあとの流れ（+24h）

    提出 → 24時間おく（レートは48〜56時間で落ち着く。24hでは途中経過）
         → agent_logs.py fetch <提出ID>      本番で落ちていないか・遅くないか
         → probe_autopsy.py <提出ID> ...      予測と実測のズレ（T1発火の判定）
         → ズレていたら記録、ズレていなければ何もしない

**24時間より早く評価しない。** 数十試合では上下に大きく振れる。
