# 審査員シミュレーター — 「どのデッキを主役にすると Strategy 部門の得点が最大化するか」

- 役: Strategy部門審査員5名(The Pokémon Company ×3 / 松尾研 ×2)になりきった採点シミュレーション
- 実施: 2026-08-06。**対戦実行ゼロ**。使ったのは一次情報の再読 + 既取得LB CSVの順位換算のみ
- 依頼元の要求: ①ルーブリック5項目の一次確認 ②5審査員×候補×配点項目の採点比較表
  ③Sim順位差の実害の定量 ④ハイブリッドの可否(規則の一次情報) ⑤評決
- **本文書は「審査員がどう読むか」の推定であり、審査員の実際の内心ではない。** 推定の根拠は
  すべて一次情報の引用に紐づけた。数値スコアは筆者(シミュレーター)の割り当てであり測定値ではない。

## 0. 評決(先に3行)

1. **主役は「タマンチュラ(ロケット団)」。ただし記事の背骨はデッキではなく“操縦者固定・デッキ可変の統制実験”に置き、
   タマンチュラはその実験が選んだ主役として登場させる。** 採点合計の推定 **84.9 / 100**(次点=オーロンゲ修理版 82.3、
   スターミー単独 75.1)。
2. **Sim順位の実害は「デッキを替えたから」ではほぼ発生しない。** 最終2枠の**片方に王者を残せば、
   LBは2提出の最大値を表示する**(自チームで実証済: 直近2=596.0/591.2 → LB表示 596.0)。
   タマンチュラを1枠使う代償は **期待値で約12レート点 ≒ 約150順位 ≒ 100点満点の0.3点**。
   一方**いま何もしないこと**の代償は 596.0 = 3,646位(上位57.8%)で **6.0点** — 桁が違う。
3. **「記事はタマンチュラ、提出はスターミー」型のハイブリッドは規則上の禁止規定が一次情報に見当たらない一方、
   採点上は不利。** Model 70% のうち**③一貫性・④マッチアップ非依存・⑤Sim成績の3項目(=全体の42%)は
   “提出されたエージェント”を対象語にしている**ため、記事の対象と提出の対象が割れると
   その42%が記事本文と接続しなくなる。**やるなら「記事=デッキ選定法、提出2枠=選定法が出した答え」型にする。**

### 2.3 判定を割った項目の理由(1行ずつ)

- **Deck 20% が最大の分岐**。①⑤(86)と②(55)の差 31点 = **加重で 6.2点**。

  これは M4 の条文「特定のマッチアップへの過度依存の回避」の**逐語的な反例**になる。
  さらに「たね1枚スタートからの盤面全滅負け 4/53」は M4 の**「特定の初期状態への依存」**にも触る。**二重に刺さる。**

  かつ修理介入が Alakazam +20.0 / Lucario +13.0 / Archaludon +13.5 と**3面すべてで有意に上げた**
  = 「マッチアップ依存を減らした」という M4 への直答になっている。
- **M3 はスターミーが最強**(88): 王者系列 747.0 / 765.0 / 783.0 / 793.9 の**4回再現**という
  公開検証可能な安定性証拠を持つのはこの系列だけ。タマンチュラは本番軌跡が
  600→836→720〜750→637.7 と**目に見えて不安定**(同節)で、そのまま M3 の減点材料になる。
- **M2 はどの候補でも高い**(72〜92)。理由は共通で、**操縦者バイト固定(md5 725ef4c9)・デッキのみ可変**という
  統制実験が公開範囲に前例ゼロ(291件監査)だから。**M2はデッキ選択にあまり依存しない。**

## 3. 審査員5人それぞれの目

配役は公表情報どおり **The Pokémon Company ×3 / 松尾研(MI) ×2**(scout-A §1.2)。
個人名は shige・choya のみ公開されており、TPC 3名の内訳は非公開。以下の3分割は
**採点行動を推定するための役割仮説**であって事実ではない。

### P1 — TPC・競技プレイ側(現実の大会を見ている人)

**読み方**: デッキリストを**リストとして**読む。60枚を目で追い、「これは誰かの構築だな」「この枠は何のため?」と問う。
CI や p 値は飛ばす。

- **タマンチュラ**: 「ロケット団のフリーザーの Repelling Veil で、フーディンの Strange Hacking を
  丸ごと無効化した」——**この1点で読み手として捕まる**。Strange Hacking は Damage 欄が n/a =
  純粋な“効果”であり、Veil の「ワザの効果をすべて防ぐ(ダメージは効果ではない)」がそれを
  完全に食う。**カード同士のテキストの噛み合わせで11勝1敗を説明している**。これは
  現実のポケカ勢が最も気持ちよく読む形。**Deck に満点近くを付ける。**
  - **ただし必ず気づく**: 「これ、ラダー最頻出リストの丸写しでは?」。team-report §6.1 が
    自分で「17チームが完全一致の最頻出形をそのまま輸入」と書いている。**隠したら即死、
    先に書けば減点は小さい。** 記事に**53戦の実測から出た改造(ミュウツーex削減・たね増量・
    ボール系追加)を1枚単位の理由つきで載せられるか**が、P1のDeck点を86にするか72にするかを分ける。
- **スターミー**: 「特性0・スタジアム0・妨害/回収/ダメカン操作0・攻撃役2種」。
  P1にとってこれは**「デッキではなく穴の突き方」**に見える。DEX 40 = 12本中最下位を
  チーム自身が測っている(deck-expressiveness §4.2)。**Deck を 50台に置く。**
  ただし条文は「概念の明確さと戦略との整合」なので、**下限は割らない**(概念は極めて明確)。
- **オーロンゲ**: 「723体中505体が同じ60枚のやつ」。**記事本文が“コピーメタ批判”を主張しながら、
  そのコピーの本体を提出している**という構図に気づく。P1のDeck点は伸びない。
- **最も効く一撃(P1向け)**: 「**AIラダー最大勢力のフーディンは、人間のシティリーグ入賞16デッキに1本も無い**」。
  P1は自分の世界の答えを知っている側なので、**自分が知らないほうの答え**を見せられると強く反応する。

### P2 — TPC・カード/ゲーム設計側

**読み方**: 「このAIは、我々が作ったカードのどこを使ったか/使わなかったか」を見る。

- **最高評価するもの**: **API 255項目のうち152が未参照、その内訳が「デッキ由来30 / 操縦者由来67 / 冗長45」**
  という分解(deck-expressiveness §1.4〜3.5)。これは**カードプールとゲームAPIの使われ方の監査**であり、
  設計側にとって直接の feedback。**2,022枚を1枚ずつエンジンに judge させて「全数使える」を確定**した
  card_support_scan、**効果10種の発火検査 10/10 FIRED** も同じ棚。**M2 に最高点を出す。**
- **タマンチュラ**: 「名前参照(Team Rocket's)でデッキが1つの機関になる」構造と、
  **Power Saver の“場に4体いないと攻撃できない”という攻撃権の条件化**を書けば、
  設計意図が読めていると判断する。**加点。**
- **P2が減点する動き**: 「効果が発動しないカードを見つけた」という主張。実際にはチームの検査で
  **エンジン側 no-op 0件・自作検査器の穴3件**だった(data.md 2026-08-04 C5)。
  **この“自分の計器のほうが壊れていた”という結末をそのまま書くと、P2の信頼が上がる。**
- **スターミー**: 「2,022枚あるのに11種類しか使っていない」。設計側として最も面白くない読み物。

### P3 — TPC・ブランド/イベント側

**読み方**: 「この記事は、外に出したときポケモンカードにとって良い話か」。物語性・図・一文で言えるか。

- **最高評価するもの**: **人間 × AI の断絶**(主砲D)。「同じ2,022枚から、5月のシティリーグと
  8月のKaggleラダーは別の答えを出した」。**決勝が東京の対面イベントである**以上、
  P3は**イベントで語れる素材**を探している。これはそのまま基調講演のスライドになる。
- **次に効くもの**: **メタが“強さ”ではなく“コピーしやすさ”で決まっている**(ρ = −0.02、
  帯の distinct 2,560体中 912体=35.6% がわずか2種類の完全同一60枚)。
  これは**AIコンペの生態そのものの発見**で、外に出す価値がある。
- **P3が最も嫌う形**: 統計記法の羅列。**Media Gallery(291件の走査+新着でも言及ゼロ=ブルーオーシャン)**に
  図を置けるかどうかで、P3のReport点が丸ごと動く。
- **タマンチュラ有利**: 「ロケット団のデッキで、AI最大勢力を11勝1敗で狩った」は**見出しになる**。
  スターミーには見出しが無い。

### P4 — MI・shige(ホスト/エンジン側の技術者)

**読み方**: エンジンの挙動を誰よりも知っている。**嘘と過大主張を1行で見抜く。**「強力で堅牢か」を最初に見る
(自身の 724094 回答の語順)。

- **最高評価するもの**: **較正の失敗を自分で見つけて公表している列**。
  ①自作Alakazamゲージが本物と **38.7pt** 乖離していた計器監査 ②公式サンプルLucarioゲージが
  較正済みゲージ比 **+46.5pt** 甘かったこと ③**同型の測定ミスを1日に4回**(数える単位・静かな打ち切り)。
  **ホスト自身がエンジンの紙ルール差分3件を公開しているように、P4は“自分の道具の限界を先に出す人”を信用する。**

## 6. Q4 — ハイブリッドの可否と是非

### 6.1 可否(規則)

### 6.2 是非(採点) — H-a(記事=タマンチュラのエージェント / 提出=スターミー)は**採らない**

**理由は配点構造そのもの。**

  M5「競技トラック内での性能」——この3項目の対象語は“提出されたエージェント”である。合計 42%。**
  記事の主役がタマンチュラで提出がスターミーだと、**42点分の採点対象が記事本文に登場しない**。
  審査員は「この報告書は、何のエージェントについての報告書なのか」で最初に躓く。**M1 が真っ先に落ちる。**
- さらに悪いことに、**記事の看板が「フーディンに11勝1敗」だと、M4 の条文
  (特定マッチアップへの過度依存の回避)に対して“自分から反例を出している”のに、
  その依存を持つエージェントは提出していない**という最悪の非対称になる。
  **依存の代償(Lucario 2-11)を負っていないのに、依存の果実(11-1)だけ主張している**構図に見える。
- shige のマルチデッキ裁定「Strategy部門ではマルチデッキ提出は肯定的に評価されない」は
  技術的には別件(1エージェント内の切替)だが、**「デッキの不一貫を Strategy で評価しない」と
  運営が言葉にした事実**は心証の推定材料になる。
- 採点推定 **75.7 / 100**(候補④)。**スターミー単独(75.1)とほぼ同じ** = **ハイブリッドの手間に見合わない。**

### 6.3 是非(採点) — H-b(記事=デッキ選定法 / 主役デッキ=タマンチュラv2 / 提出=タマンチュラv2 + 王者)は**採る**

**H-a との違いは1点だけ: 記事の「モデル」を“1つのデッキを積んだエージェント”ではなく
