## 3. 任務2 — 現職衰退分析(我々にしか出来ない本丸)

`python3 replay_analysis/meta_timeline.py plan|fetch|panel` → `python3 replay_analysis/incumbency.py 800 1100`

### 3.1 H2は死んだ — 後発コホートは弱くない(単位=個体)

参入週コホート → 均衡レーティング(31戦目以降の中央値、40戦未満は除外・開示):

週次レーティング中央値でも同じ(7/28週: grimmsnarl 後発1014 vs 現職956 / tarountula 後発960 vs 現職915)。
**「弱い操縦者が量産されてシェアの勝率を薄める」という構成効果は、レート上は観測されない。**
alakazam に至っては**後発ほど有意に強い** = 公開素材(ノートブック)の質の向上をコホートが追跡している

### 3.2 H1は「シェア特異」としては支持されない — 現職は全員沈む(単位=個体)

- 現職の下降そのものは**実在**(両仕様で有意)。ただし**下降速度の順位は仕様で入れ替わる**
  (厳格: alakazam最速 / 緩和: grimmsnarl最速)。**「最も真似されたデッキが最も狙われる」を

- 同時に観測プールは深化している: 観測側スコア平均 876(7/07週)→ 960(7/21)→ 956(7/28)、

  現職全員から点を奪う。**アーキタイプを問わず現職が沈む観測は、対抗適応より先にこの機械で説明がつく。**

  帯・レート条件付きの上記分析が下限の主張。

バケット間で個体集合が入れ替わる(121→2)+ 若い個体はレートが実力に遅行し正残差が機械的に出る
(Elo 収束)+ 古い個体はゲーム頻度が落ち K も縮む。**分解には至らなかった**(正直に不足と記す)。
方向の示唆に留める。

## 6. 限界(先に自分で書く)

1. **標本フレーム**: decks.jsonl は我々の対戦近傍のスノーボール標本。採用曲線の6月分は過小。
   全ラダー無作為ではない(SUMI系列との方向一致で補強したが、点推定は我々の帯の近傍に条件付き)。
2. **相手アーキ既知率 37.3%**(パネル)/ 早期週の未知率 84.9%(シェア表)。未知は無作為ではない
   (死んだ個体・遠い帯に偏る)。
3. **現職の個体数**: 厳格仕様で 5〜6体、緩和でも 8〜10体。シェア特異的下降の検定力不足。
   追加取得102体(grimmsnarl現職35・archaludon25・alakazam早期15・crustle15・lucario12)は
   レート制限(HTTP 429)で微速。**バックグラウンドで低速続行中**(バックオフ5s→倍々→120s上限、
   直列1接続)。次セッションは `meta_timeline.py fetch` 再実行→ `panel` → `incumbency.py` で
   この節の数字を無改修で強化できる。
4. **残差の物差し**: P(win|Δ) は全期間プール。期間別の物差しの歪みは未検証(全体残差が各週≈0で
   大きな歪みは見えないが、定量はしていない)。
5. **4.2 の加齢減衰は分解不能**(個体入替+Elo収束+K縮小の混合)。
6. マッチメイキングのガウス窓により、全ての「シェア」は**レート条件付き遭遇シェア**。
   母集団シェアと呼ばない。
7. 相関はすべて k≤9。**ρ の符号と外れ値の同定**が主張であり、係数の精度は主張しない。
