## 節構成と語数予算（合計 ~1,950語 + タイトル/サブタイトル）

### 0. Title / Subtitle
- 主張を一文で。例:「Measure Before You Believe: ローカル検証基盤で仮説を潰しながら作る PTCG エージェント」（仮。最後に決める）

### 1. Approach Overview — なぜこの戦略か（~250語）
- 配点対応: Model①
- 内容: 「閉じた自己対戦は自分に甘い」という中心課題を先に宣言し、
  仮説→ゲージ実測→採否のループ（D8/D9）を方法論として提示。
- 素材: decisions.md D1〜D10、handover §7（自己申告弱点）
- 穴: なし（書くだけ）

### 2. Pilot Design — 意思決定ロジック（~450語）
- 配点対応: Model①②
- 内容: 貪欲方針＋ダメージ評価器＋リーサル判定＋契約堅牢性（D8）。
  ダメカン乗せは弱点・抵抗を通らない別レーン、という実機検証由来の設計判断が独自性の種。
- 素材: D8、data.md cabt実機検証（Powerful Hand 15/15一致）
- **穴A: 消化済み・方向転換**（2026-07訂正）。エンジン同梱探索(v2〜v2.1c)は採用・提出済み
  (D13-D15)。決定化MCTS拡張(v3)は対照実験付きで**棄却**(D18-D19、機構=対標本差分推定器の
  破壊)、第2世代iter4のクラス限定上書きも4役評議会で**棄却**(D24、機構=上書き価値がクラス
  ×対面×デッキの三重交互作用で固定allowlistが構造的に成立しない、D25で実証)。
  **独自性の主砲はMCTS自体ではなく、この一連の対照実験付き負の結果と機構解明そのもの**
  (D19「決定化MCTSは教科書で差別化不可、197本中に同型多数」の判断は据え置き)。

### 3. Verification Infrastructure — 安定性と頑健性の実証（~400語）
- 配点対応: Model③④（← うちの検証基盤が最も直撃する節）
- 内容: bench（95%CI付き）/ 3ゲージ / donk_meter / デッキ総当たり。
  「同一エージェント2連投で150〜400点差」というLBの分散問題（D11-4）を引用し、
  ローカル大量対戦がLBより情報量が多いことをデータで主張する。
- 素材: data.md ベンチ表・総当たり表、Scoring Inconsistencyスレ（公開情報として引用可）
- **穴B: 実メタ対応の頑健性マトリクス**。ゲージは自作AI＝下界でしかない（D8注意書き）。
  上位メタ実勢（Alakazam/Dudunsparce・Mega Kangaskhan・Crustle/Munkidori）の再現デッキ
  を相手にした勝率マトリクスが必要。
- **穴C: 初期状態依存の定量化**。マリガン率46%・basic1枚スタート74%→即死5/8敗の観測を
  「初期状態に依存しない設計にどう反映したか」まで繋げる（Model④の直答になる）。
  進捗(2026-07-21): R1実験(棄却)の副産物としてdonk早期敗北率8.0%→3.8%(2.3σ)の
  探索的示唆を確保。donk主指標での単独再検証が次の一手。
- **穴C追加素材(2026-07-21確定)**: 実ラダー60戦の遭遇分布×勝敗（生存バイアス除去済み）
  = Model④「マッチアップ非依存の頑健性」に直答する一次データ。Archaludon対面が勝率20%
  (損失寄与最大)、Lucarioは遭遇率最多だが勝率50%、と定量化済み。図1(頑健性ヒートマップ)
  ・図2(レーティング時系列)は docs/memo/figures/ に生成済み。

### 4. Deck Construction — デッキ選択の論理（~350語）
- 配点対応: Deck 20%（単独で配点2割。手を抜かない）
- 内容: デッキ=操縦者とセットでしか測れない（D9の発見）→ 総当たり＋専用ゲージの
  二重測定でサンプル維持を選んだ判断過程。キーカードの役割を1枚ずつ言語化。
- 素材: D6（デッキ5原理）、D9、data.md 総当たり表
- **穴D: 最終デッキの確定実験**。メンバーagent（mega-starmie-ex-deck）との統合判断を含む。
  弱点マップ実測（次タスク）がここの弾。

### 5. Results — Sim部門での成績と較正（~300語）
- 配点対応: Model⑤③
- 内容: 提出履歴（413.4→600→…）とローカル指標の相関、リプレイ解析による敗因の
  実測（0ダメ攻撃10連発の24ターン負け等）→ 修正 → 再測定のループを時系列で。
- 素材: data.md 提出履歴・リプレイ監査
- **穴E: ベスト版の再提出**。(2026-07-22更新) 直近2提出=54858780(EXP8, 742.5上昇中)+
  54832323(v2.2, ~785)で健全。8/13朝に同一ベスト×2で確定（D11-4の実務解、提出規律ドラフト）。
- 注意: リプレイJSONのselected 1手ずれバグ（D11-3）。replay_analysis を教師データに
  使うなら補正必須。

### 6. What Didn't Work & Limitations（~150語）
