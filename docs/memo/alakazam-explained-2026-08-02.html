答え

車は「より正確」でした。ドライバーは「圧倒的に下手」でした。

車(デッキ)— これは我々が正しかった

ただし「良いものを発明した」のではありません。「本物を正確に写し取っていた」です。 ここは大事な区別です。デッキは相手のものを観察してコピーするもので、独創性の話ではありません。

実際の対戦記録から、アラカザムのデッキを27種類・延べ52戦ぶん全部抜き出して照合しました。 「よく当たる型ほど重く数える」やり方で採点したのが下の図です。60点満点 = 完全一致。

なぜ我々の方が正確だったのか。 公開ノートブックを書いた人は「自分が使っている1つの型」を載せます。 我々は本番の対戦記録を全部見て、一番よく当たる型を写した。だから実ラダーに近くなった。 やり方が正しかったということです。

アラカザムの攻撃は「手札の枚数 × 20ダメージ」です。だから手札を減らす行動は、そのまま自分の火力を下げる。 本物はそれを数えて動きます。我々の自作は、自分の火力を一度も計算していませんでした。

0344ptのズレは、どこから来たのか

車とドライバーを1つずつ本物に替えて測りました。各300戦。我々側(スターミー)は一切変えていません。

読み取れること
  • 車を直すと 7.0pt 下がる — デッキの誤りの寄与
  • ドライバーを直すと 31.7pt 下がる — 操縦者の方が4.5倍効く
  • 両方直すと 57.3%。本番の 51.7% との差は 5.6pt で、誤差の範囲内 — つまり新しい練習相手は本番を正しく写している

この 31.7pt は「車を固定してドライバーだけ入れ替えた」数字で、D27で発見した較正の法則とまったく同じ測り方です。 既存の3点(steel +62 / 公式ルカリオ +41 / りょーちん +8)に、4点目として並びます。 ただし正式に主張へ昇格させるには事前登録の手続きが要るので、今日はまだやっていません。

04質問②への答え — 「相手の山を自分の山と誤読」とは

あなたの質問

「相手の山を自分の山と誤読します」ってわけわからん。どういうこと?

説明が雑でした。コードのたった1行の話です。

file_path = "deck.csv" ← 「いま居る場所にある deck.csv を読め」という意味

"deck.csv" のようにフォルダ名を書かない指定は、「今いる作業フォルダ」を探しにいきます。 同じ1行が、置かれる場所によって別のファイルを読んでしまう。

✓ Kaggle本番では正しい
相手AIの部屋/ ├ main.py ← 相手AI └ deck.csv ← 相手自身のデッキ ✓

相手AIは自分専用の部屋で動くので、そこにある deck.csv は当然「自分の山」。正しく読めます。

✗ 我々のローカル練習では壊れる
starmie-aggro/ ← ここで実行する ├ main.py ← 我々のAI └ deck.csv ← 我々のスターミー ✗

練習は我々のフォルダで走らせるので、相手AIが読むのも我々の deck.csv。相手が「自分の山はスターミーだ」と思い込みます。

なぜそれが問題なのか

このアラカザムAIは、「山にアブラ/ユンゲラー/フーディンが何枚残っているか」を常に数えながら戦います (作者本人が手順書にそう書いています)。数える対象の山を取り違えたら、その計算は全部狂う。 結果として、本来より弱く — あるいは奇妙に — 動く。そのまま測った勝率は嘘になります。

なので、持ち込むときに「このファイルの隣にある専用デッキを読め」という絶対的な指定に書き換えました。 意思決定のロジックには一切触れていません。

あなたの質問

答え

直しています。記憶は正しい。ただし直したのは別の場所で、今回は新しく持ち込んだ他人のファイルに同じ罠が最初から入っていました。

7/30 に直したもの今日 直したもの
どこ我々の main.py を相手役に使うとき今日ダウンロードした他人のファイル
直し方infamily_probe.py という専用ハーネス側でデータを上書き。main.py は無編集ファイル本体を絶対パスに書き換え
効き方その専用ハーネスを使ったときだけ直るどこから呼んでも直る(より強い直し方)
実際の被害罠は実在したが、影響は 0.00pt(±6.4)で検出されず設置前に潰したので未発生
記録D59 / 台帳#31D61

「直したものが壊れた(退行)」ではありません。 「同じ形の落とし穴が、新しく持ち込んだファイルにも最初から掘ってあった」という話です。 "deck.csv" という書き方は誰でもやる自然な書き方なので、外部のコードを取り込むたびに毎回チェックが要る種類の罠です。

⚠ 誤解しないでほしい点

今回の 44pt のズレは、このバグのせいではありません。 3段分解の測定はバグを潰した後に行っています。 ズレの原因は純粋に操縦者の腕前の差(31.7pt)とデッキの誤り(7.0pt)です。

06ついでに見つかった、もっと大きな問題

公開されているノートブックを291件すべて数えました。我々が取り込んでいたのは6件(2.1%)だけでした。

playbook には「週に1回、外部の公開情報を取り込む」というルール(T5)が書いてあります。 自分たちで作ったルールです。それが回っていませんでした。

  • ある人が69体のエージェントの総当たり表を公開している(我々は5体を手作りしていた)
  • 公式サンプルの4体目を取り忘れている
  • 我々に練習相手がいないクラブ(壁)やガブリアスのエージェントが公開されている
  • Elo 1208 / LB 1084.5 級の上位エージェントが公開されている(我々の最高は 783.0)

公開の締切が今夜(日本時間 8/3 朝8:59)だったので、70件をダウンロードして退避しました。 既に公開されたものは締切後も読めるので、読むのは後日で構いません。取り逃しだけ防いだ形です。

これは悪い話に見えて、レポートの材料としてはかなり強いと思っています。 playbook にはこう書いてあります — 「内向き防止の本丸は、自己懐疑ではなく外部証拠の摂取」。 その仕組みを作った本人が回せなかった、という実例が手に入りました。
