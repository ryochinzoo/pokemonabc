### ★過分散への備え(T7統計レンズの指摘を反映)

二項SEだけを見ると SE_diff = 0.553pt、MDE80 = 1.55pt。**しかし `cew.py:66` は、
同じ腕を2回測ると実測SDが二項SEの 1.40倍だったことを記録している**
(χ²(1)=1.95 は「過分散なし」ではなく「検出できず」と読む、とも書いてある)。
さらに 2026-08-09 のデッキ探りでも、ブロック間で ΔG が +8.0/+18.0 と 1.45σ ぶれた。
**弱い信号が2つ、同じ向きに出ている。**

| 分散モデル | SE_diff | MDE80 | 検出力 @+1.69pt |
|---|---|---|---|
| 二項のみ(初版の前提) | 0.553 | 1.55pt | 86% |
| **×1.41(実測の過分散)** | **0.777** | **2.18pt** | **59%** |

`cew_stats.py` は二項分散しか計算しないので、**登録した判定規則からは過分散が原理的に見えない**。
→ **2ブロックではなく6ブロックに割り、主判定のCIを「ブロックごとの合成差の batch-means CI」
(`d̄ ± t₅·sd(dⱼ)/√6`)にする。** 追加コストは 24戦/腕(+0.4%、約1.4分)。
過分散が実在すれば閾値が自動的に締まり、無ければ締まらない。**自己較正する。**
副次出力として **λ̂ = sd(dⱼ)·√6 / SE_binomial** を報告する(D69以来の未決問題の決着)。

### ★「検出力87%」の正しい読み方(T7の指摘を反映)

86%は**予測が正確に当たった場合の条件付き検出力**であり、
上の予測区間([−1.5,+5.0] ⇒ 事前SD 1.66pt)と**同時には主張できない**。

| 織り込むもの | 「検出した」と言える確率 |
|---|---|
| 予測が正確(初版の書き方) | 86% |
| **+ 登録した予測区間** | **64%** |
| + 過分散 λ=1.41 | **49%** |

**約3回に1回は、12,000戦・6時間かけて何も決まらない。** これが過剰修正のリスクの数値である。

**さらに、+1.38pt という「デッキ実測値」も定数ではない。** v2 の他4セルは
2026-08-06 の単一測定 N=200 なので、伝播させると **SE 1.20pt、95%CI [−0.98, +3.74]**
= **ゼロと区別できない**。3修理(+0.31点予測、上限+1.39、VETO下振れ−1.46)を足すと、

**勝者の呪いの縮小**: ΔG=+13.0 を事前分布(μ=+9.5, τ=6.89)で縮小すると **+12.3**、

## 5. ★判定規則(3分岐。N は §3 で凍結済みなので後から動かせない)

主判定は **5面合成の差の95%CI**(`verification/cew_stats.py`)。**点推定が閾値を跨いだかでは判定しない。**

| 観測 | 判定 | 帰結 |
|---|---|---|
| **CI下限 > 0** かつ **点推定 ≥ +2.0pt** かつ 安全ゲート全通過 | **効果を検出し、採用域** | **8/11 の枠で v2 を提出**(ゆうじの承認を取る)。層Bへ昇格、記事に引用可。**T4懐疑パス(ベイズ検査+ラダー予測の事前登録)を提出前に通す** |
| **CI下限 > 0 だが 点推定 < +2.0pt** | 効果はあるが**採用域に届かない** | 提出しない。pilotfix で凍結。「効果は検出したが D29 の採用閾値未満」と記録 |
| **CI が 0 を含む** | **検出できず** | 提出しない。pilotfix で凍結。「N=12,000 でも見えなかった」と記録 |
| **CI上限 < 0** | **v2 は有害** | 提出しない。v2系統を打ち切り、記事に negative result として書く |

### ★★訂正(2026-08-09、T7統計レンズの指摘を検算して確認)— 私はゴールポストを動かしていた

本登録の初版は、判定を「差 > MDE」から「CI下限 > 0」に差し替え、その理由を
**「MDE は N 依存だが CI下限>0 は N 非依存だから、緩和ではなく訂正である」**と書いた。
**この主張は数学的に誤りである。**

- `CI下限 > 0` ⟺ `d > **1.96**×SE(N)`
- `d > MDE80`  ⟺ `d > **2.8016**×SE(N)`

**どちらも SE(N) を含むので同じくN依存。** 私が実際に変えたのは**定数だけ**である。

| 基準 | 点推定の閾値 |
|---|---|
| ゆうじが承認した `d > MDE80` @ N=2,402 | **2.431pt** |
| `d > MDE80` @ N=6,000 | 1.538pt |
| **初版が登録した `CI下限 > 0` @ N=6,000** | **1.076pt** |
| D29 の標準採用閾値(SEを含まない=**真にN非依存**) | **2.000pt** |

**承認された基準から 56% の緩和**(N増加で37%、規則の差し替えでさらに19%)。

**決定的な検査**: 昨日 D70 で「基準未達」として見送った **+1.38pt** は、
旧基準では**見送り**(1.38 < 2.431)、初版の新基準では**提出**(1.38 > 1.076)になる。
**同じ数字で決定が逆転する。数字を見た後に規則を変えた = ゴールポストを動かした。**

**訂正の内容**: D29 の標準採用閾値 **+2.0pt を主判定に戻す**(これだけが真にN非依存)。
`CI下限 > 0` は「効果が検出されたか」を見る**併用条件**として残す。両方満たしたときのみ提出。
**登録した期待効果 +1.69pt は +2.0pt を下回る**ので、**予測どおりに出たら提出しない**。
これは不都合だが、事前に書いておく。

**安全ゲートは効果量と独立に課す**(D29: 独立ゲートを効果量に増やさない):
両腕 vs random **≥96%** / CRASH=0 / `conformance.py` PASS / `check.py --submission`。
**1つでも落ちたら効果量に関わらず提出しない。**

## 7. ★正直に書いておく下振れ要因

### ★★訂正(2026-08-09、T7前提レンズの指摘を検算して確認)— 初版の「リスク」2件は誇張だった

初版はここに「VETOの下振れ −1.46pt(実測)」と「どうぐ項欠落でv2は過小評価される」を書いた。
**両方とも証拠が主張に足りていなかった。** しかも**互いに逆方向を向いている**ので、
片方向の動機づけではなく、**どちらも根拠を確かめずに強く書いた**という誤りである。
2026-08-09 に自分で記録した「N=12 から乖離を語ってはいけない」の再演。

**① VETO の「−1.46pt」は実測ではない**

出典 `data.md:5241` は**1回のトレース**(v1=1431/探索=131 → v1=1432/探索=117、約1,560決定 ≈ 10戦)。
**Δ=14 に対し Poisson の SE ≈ 15.7 で、ゼロと区別できない。**
しかも出典自身が「**探索そのものの出番はほぼ変えていない**」(`data.md:5242`)と結論している。
さらに `data.md:5329-5332` は、131件の探索決定のうち v1 がどうぐ貼りを答えていたのは**4件**で、
そこで探索が選んでいたのは RETURN×2 / どうぐATTACH×2 / **ATTACK 0件**と列挙している。
**VETO が潰す集合は探索決定の約0.9%で、しかもランダムな抽出ではない。**
→ **正しい記述: VETO の効果は未測定。footprint は決定の約0.9%。有害とも無害とも言えない。**

**② 「どうぐ項の欠落で v2 は過小評価される」は機構が不活性**

- **バングルの+30は「同じバトル場ポケモンの全ワザ」に共通の定数**なので、
  攻撃選択の argmax(`main.py:684-694` の `dmg > attack_dmg`)を**動かせない**。
  リーサル加点 `+10000` も、定数を足して初めてリーサルになるワザは
  **もともと最大打点のワザ**なので、やはり argmax は変わらない。
- **+30 は「相手のバトル場が ポケモンex」のときだけ**(カードテキストで確認)。ゲージ別の ex 枚数:

| ゲージ | 重み | 相手デッキの ex | バングル |
|---|---|---|---|
| フーディン | 0.3399 | **1枚**(Fezandipiti ex。主砲の Alakazam 743 は非ex) | **ほぼ死に札** |
| イワパレス | 0.1572 | **0枚** | **完全に死に札** |
| オーロンゲ | 0.2247 | 3枚(主砲) | 生きる |
| メガルカリオ | 0.1537 | 4枚(主砲) | 生きる |
| ブリジュラス | 0.1246 | 4枚(主砲) | 生きる |

  → **合成重みの 49.7% でバングルは事実上効かない。**
  これは 2026-08-08 に T7 が既に指摘し(`data.md:5320-5323`)、初版はそれを落としていた。
- **残差の符号はむしろ逆の可能性がある**: `_tool_kinds` は {ex} 条件を落とすので、
  上の49.7%の帯でも**バングル貼りを `useful=1` と採点して優先してしまう**。
  **v2 はバングル3枚なのでこの誤りを3倍払う。**
- 「3倍」自体も**枚数比を発火率比として語ったもの**で、発火回数は数えていない
  (`data.md:5245` 「先に見るのは勝率ではなく発火」に反する)。

→ **正しい記述: どうぐ項の欠落が v2 の測定値に与える符号は不明。**
  **「v2の伸び代」として記事にも判定にも持ち込まない。**
