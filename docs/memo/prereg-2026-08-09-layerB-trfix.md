`decisions.md` の記録上、**層B(採用判定)に昇格した測定は1本も存在しない**
(handover-2026-08-07:102「まだ1本も昇格していない」)。原因は受け皿の故障で、

2026-08-09 にこれを修理した(D69)。その結果:

- Neyman配分 N=3,200/腕 で **80%検出力のMDE = 1.87pt**(旧設計は 2.67pt)
- **実装済み修理の実測差 +1.94pt が、初めて検出圏に入った**

記事(賞金はStrategy部門)の看板数値は層B必須(T6)。**本測定はその1本目を取りに行く。**

## 2. 何を測るのか — 変数は1個

デッキを**バイト同一に固定**し、操縦者だけを差し替える。

| 腕 | ディレクトリ | main.py md5 | deck.csv md5 | 中身 |
|---|---|---|---|---|
| **A: pilotfix** | `deckswap-tarountula-pilotfix` | `3f55780b` | `a246be4f` | **実ラダーに現在載っている腕**。TRFIX束あり |
| **B: P9素** | `deckswap-tarountula` | `725ef4c9` | `a246be4f` | TRFIX束なし。ep55236642 として実ラダーで走った腕 |

TRFIX束の中身(`data.md:4718-4726`):
① 攻撃560(ロケットラッシュ)・609(ロケットミラー)を `_SCALING_DAMAGE` に登録
② デッキのエネ型でワザを絞る `_deck_energy_types`/`_payable`/`_usable_attacks`
③ (掃引後に追加)契約チェック2箇所 — 挙動不変を556,092回で確認済み

**⚠ 正直に言う限界**: pilotfix 内の `V3_NO_TRFIX` は①②の**両方**を同時に切る
(`:45` と `:306` の2箇所)ので、**本測定は束の効果しか出せない。①と②の寄与は分離できない。**
これは「束ねて測るな」への違反ではなく、**既に出荷済みの成果物を測る**ため。
分離が要るなら別途トグルを割る実験を立てる(本測定の射程外)。

## 3. 設計

### 3.1 配分(`cew.py` の Neyman配分をそのまま使う)

| セル | ゲージ | 重み | N/腕 |
|---|---|---|---|
| フーディン | `reference/alakazam_ryota_agent.py` + `decks/ryota_alakazam_2026-07-05.csv` | 0.4384 | **1248** |
| イワパレス | `reference/soutasakurai_crustle_agent.py` + `decks/soutasakurai_crustle_2026-08-04.csv` | 0.2027 | **380** |
| メガルカリオ | `reference/makthanithin_lucario_agent.py` + `decks/makthanithin_lucario_2026-08-05.csv` | 0.1982 | **934** |
| ブリジュラス | `reference/tomato_archaludon_agent.py` + `decks/tomato_archaludon_2026-07-22.csv` | 0.1607 | **638** |
| 安全ゲート | random | — | 240 |

**合計 6,400戦 + ゲート480戦。** 全セル偶数(`run_series` が `i%2` で席を入れ替えるため)。
**直列**(我々の操縦者が実時間予算 `_SEARCH_BUDGET_SEC=0.6`。playbook §2)。
実測から見積もった所要 = **1腕約84分 / 全体約2.9時間**。

### 3.2 前回の設計欠陥を潰す点(これが本測定の存在理由の半分)

1. **対照を同じ走行・同じドライバ・同じ日に測る。** 2026-08-06 の掃引では P9素の4セルが
   3〜5日前の**別ドライバ・別ディレクトリ**由来(alakazam/archaludon=08-03、crustle=08-04、
   lucario=08-05 は `deckswap-tarountula-sweep` で測定)だった。
2. **族内ゲージ(オーロンゲ)を入れない。** 判定に使えないセルにCPUを払わない
   (前回は所要の70〜90%をそこに払っていた)。
3. **env を全数固定し、実効環境を各セルの直前にログする**(`echo_env` を実際に呼ぶ)。
   `env $var` の展開は使わない(zshで無音失敗する)。
4. **基準線は単一測定に置かない。** 本測定の腕Aが3反復目になる(08-06 / 08-09 / 本測定)。

### 3.3 測定前の妥当性検査(対戦ゼロ、これに落ちたら起動しない)

- **V1**: `deckswap-tarountula-pilotfix` に `V3_NO_TRFIX=1` を掛けた実装が、
  `deckswap-tarountula`(P9素)と**決定レベルで一致**することを `verification/equiv_probe.py` で確認。
  → 一致率が 100% でなければ「腕Bは腕Aのトグル違いではない」ことになり、
    束の同定が崩れる。**その場合は差分を精査してから起動する。**
- **V2**: 両腕の `deck.csv` md5 が `a246be4f` で一致することをドライバがログに出す。
- **V3**: `conformance.py` が両腕で `CONFORMANCE=PASS`。

## 4. ★凍結する予測(測定前に書く)

出典は 2026-08-06 掃引(腕B・N=200/セル)と 08-06+08-09 合算(腕A・N=400/セル)。

| セル | 腕B P9素(予測) | 腕A pilotfix(予測) | 差の予測 |
|---|---|---|---|
| フーディン | 92〜96% | 90〜95% | **0 ± 3pt** |
| イワパレス | 92〜97% | 96〜100% | **+2 ± 3pt** |
| メガルカリオ | 11〜18% | 14〜21% | **+3 ± 4pt** |
| ブリジュラス | 6〜13% | 9〜16% | **+3 ± 4pt** |

- **合成の点予測: 腕A − 腕B = +1.9pt。95%予測区間 [−1.0, +5.0]。**
- 安全ゲート予測: 両腕とも vs random **≥ 96%**、CRASH = 0。
- 腕Aの合成の点予測 **65.7%**(3反復合算に向かう)、腕B **64.8%**。

**予測区間を広く取った理由**: 腕Bの4セルは別々の日・別ドライバで測られた歴史的値であり、
同一走行で測り直すと系統的にズレうる。**ズレたらそれ自体が発見**(T1較正の材料)。

## 5. ★判定規則(3分岐。どれに落ちても情報が残る形にする)

主判定は **合成の差 と その95%CI**(`cew_stats.py`)。点推定が閾値を跨いだかでは判定しない。

| 観測 | 判定 | 帰結 |
|---|---|---|
| **CI下限 > 0** | 修理の効果を**検出** | **層Bへ昇格**。記事の看板数値として引用可。台帳へ登録 |
| **CI が 0 を含む** | N=6,400 でも**検出できず** | 昇格しない。記事には「**この規模でも見えなかった**」と書く。実ラダーの +1.7pt(CI重複)と整合する negative result として扱う |
| **CI上限 < 0** | **修理が有害** | **凍結前の最終2枠の中身を見直す**。実ラダーの全対外(P9 約50% / pilotfix 約43%)と整合してしまう。この場合 P9素 の再提出を検討し、ゆうじの承認を取る |

**採用閾値との関係**: `cew.py` の +2.0pt は「採用検討に入る」線であって、
本測定の主判定ではない。**主判定は 0 との関係**(効果の有無)。
+2pt を超えたかは副次で、超えた場合も **argmax腕は独立追試が要る**(D26 勝者の呪い)。

**この登録に「確実な勝ち」を仕込んでいないことの自己申告**:
上の3分岐は排他かつ網羅で、**どれに落ちても事前に定めた帰結がある**。
特に3行目(有害)は、**現在ラダーに載っている我々の提出を否定する**分岐であり、
実ラダーの全対外の数字はむしろこちらを支持している。
(2026-08-08 の「メガルカリオ30%超えたら負け」= 真値8%・P≈2×10⁻⁵⁹ のような
 偽の反証条件は書いていない。)

## 6. kill / futility

- **futility**: 腕Aの安全ゲートが 96% を割った時点で全体を中止(正当性の欠格)。
- **中断時の扱い**: セル単位で完走した分だけを報告し、**未完セルは合成に入れない**
  (欠けたセルの重みで再正規化すると別指標になるため、その旨を明記して報告する)。
- **タイムボックス**: 4時間。超過したら中止して部分結果を層Sとして報告する。
