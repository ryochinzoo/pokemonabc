## エンジン同梱探索API PoC (2026-07-15, 穴A可否検証)

エンジンには**エージェント用探索APIが公式に組み込み済み**（Export.cpp/Search.h/Api.h、ソースはKaggle Dataページ ptcg_engine、ライセンス=大会期間内利用限定のためリポジトリ非同梱・scratchpad保管）。

- 仕組み: 毎観測に `obs["search_begin_input"]`（相手非公開情報を消去したシリアライズ盤面base64）が**本番・ローカル共に既に入っている**（kaggle-environments cabt.py L187で確認）。`AgentStart()`→`SearchBegin(盤面, 自分の山札/サイド・相手の山札/サイド/手札の推定=決定化, enemyActive, manualCoin)`→`SearchStep(searchId, 選択)`で分岐状態を無限に展開。`shuffle`で再決定化、`SearchRelease/SearchEnd`で解放。**両プレイヤーの手を自分で選んで進められる**＝MCTS/expectimaxの土台そのもの。
- PoC実測（member機、ターン2起点、決定化1本）: **23,666 SearchSteps/秒**（JSON往復込み）。ランダムプレイアウトは約200step/本→**約100プレイアウト/秒**。手番600秒のovergage予算に対し余裕が桁で違う。
- 検証スクリプト: scratchpad/poc_search.py（determinize: 自分の未見カード→山札+サイドに分割 / 相手の60枚仮定→サイド+手札+山札に分割）。
- 含意: 相手デッキの推定（アーキタイプ判定→60枚仮定）が探索の入力になる → メタ観測(7/14)の実リスト5種がそのまま推定辞書になる。

## ★★機構の再特定: 上書きマージンは評価スケールに対して無効だった (2026-07-25、コード実読)

T7パネルの指摘M2を**自分で一次資料を読んで検算し、確認した**。

### `_evaluate`(`starmie-aggro/main.py:709-744`)のスケール階層

| 項 | 行 | 値域 |
|---|---|---|
| 終局(勝ち/負け) | 714 / 716 | **±1e9** |
| サイド差 1枚あたり | 721 | **±10,000** |
| エンジン拒否手 | 855 | **−1e6** |

対して上書き発火の唯一の条件式(`:896`)が使う **`_OVERRIDE_MARGIN = 120.0`**(`:605`、
著者注記「(盤面項スケール)」)。

  +5e8 となり、マージン120は無いに等しい。
- → **上書き判定は「盤面評価が明確に優る手を選ぶ」ではなく、
  「どれかの決定化で勝ち筋/サイドを引いた候補を選ぶ」宝くじ最大化として動作している。**

### D18の機構帰属の訂正(自己批判)

- D18はv3の失敗を「**訪問数不均等**下の平均比較による最大化バイアス」と記述した。
  しかし現行の探索(`:839-886`)は**全候補を毎回評価**し、予算が一度も作動しない以上
  `counts[c]` は全候補で det に等しい。**訪問数の不均等は現行コードには存在しない。**
- `:887` の `counts[c] >= _DETERMINIZATIONS` フィルタも、等号が常に成立するため**空振り**。
  「det=1ならフィルタが緩む」というE4初版の予測(根拠)は**成立しない**。
- **実在する機構は訪問数ではなくスケール階層**である。最大化バイアスは
  「重い裾を持つ評価値の argmax」から来ており、**サンプル数を増やしても裾は消えない**。
- これは「(4) 自己一貫性が det に対し平坦」という実測と**整合する**
  (裾由来のバイアスは平均化で消えない)。**測定とコード読解が独立に同じ結論に到達した。**

### なぜ `min` が det より効いたのかが、これで説明できる

`min` は「**全ての**決定化で良い候補」しか選ばないため、宝くじ当選を直接無効化する。
サンプルを増やす(det↑)のは当選確率の推定を精緻にするだけで、当選そのものは止めない。
**発火率の実測(mean/k=2:16.4% → min/k=2:12.9% > det4倍のmean/k=8:14.1%)は、
この機構から予測される順序と一致している。**

### 記録上の帰結

- **E4の主軸は「計算量」ではなく「推定量(と評価値のスケール)」に差し替える。**
- **D51の「E4継続の根拠」を差し替える**: 「本番予算利用率0.2%」は弱い根拠(使い道が
  無いだけかもしれない)。強い根拠は「**評価関数のスケール階層に対してマージンが
  無効であり、無料で直せる推定量の欠陥がある**」。古い理由を記録に残すと、
  次回も0.2%で実験を正当化してしまう。
- 台帳候補: 「我々は自分の探索の失敗機構をD18で誤特定しており、7ヶ月後に自分で訂正した」
  = E1/E2/E3三部作(存在→発生→純効果→正当性)に続く**第4話(機構の誤特定と訂正)**。
